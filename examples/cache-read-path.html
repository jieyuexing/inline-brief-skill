Two-tier read path (hover a node, or step through below)
Sample load test · illustrative numbers
Claim: a request only reaches Postgres after both tiers miss, and the answer is written back to both so the next read is local.
Walk one cold read
Click a step or press Play; the diagram above follows along
The handler asks L1 first. A hit returns in well under a millisecond and the walk ends here.
The key is absent or expired locally, so the same key is fetched from Redis over the network.
Only now does the request reach Postgres. A single-flight lock keeps concurrent misses on the same key down to one query.
The row is written to Redis and L1 with a jittered TTL, so the next reader stays on the fast path.

Method and how to reproduce (expand)
All figures are illustrative sample data for this demo, not a benchmark of any real system. To collect equivalent numbers on your own service:
redis-cli --latency-history -i 1
psql -c "EXPLAIN (ANALYZE, BUFFERS) SELECT * FROM items WHERE id = 42"
for i in $(seq 200); do curl -s -o /dev/null -w "%{time_total}\n" localhost:8080/items/42; done | sort -n | tail -3
